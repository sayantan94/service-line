What the search changed

  • Every step is marked agent or engine. Stripe's agents run on templates where formatting, linting and tests are fixed code and only the thinking is left to the agent. Stripe, ByteByteGo
  • Two repairs, then stop. Stripe caps its retry rounds at two for the same reason. MindStudio
  • Hidden scenarios. StrongDM keeps its test scenarios where the coding agent cannot read them, so the agent cannot build to the test. Simon Willison
  • Research before Plan, and plans in small phases. Both are common in published agent workflows. Eden AI, Playbooks
  • A fresh agent reviews. An agent reviewing its own work misses its own mistakes, which is why the plan review and Verify use the other agent. Playbooks
  • No workflow server. For one machine, saving state at each step boundary is enough; a server such as Temporal is more than this needs. Tian Pan, Developers Digest
  • Run log, recovery, sandbox, guards and the agent contract. These follow the source code of an open-source agent harness. Service Line adds a time limit per step and a hard stop for stuck agents, which that harness leaves out. DeepSeek Harness
  • Reset before retrying. Re-running an agent on a half-changed checkout gives different edits each time, so a retry starts from the last checkpoint. Engineering Playbook

Except for the harness, which was read at source level, these come from write-ups about those systems, several of them second-hand.
