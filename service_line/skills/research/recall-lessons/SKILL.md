# Recall lessons

Stop the same mistake being made twice by applying what earlier work on this service already established.

## Do

1. Read the lessons provided for this service. If none are provided, say so in one line and stop.
2. For each lesson, decide whether it applies to this request's code area and kind of change.
3. For each lesson that applies, state what it means here: the specific check to add, the case to cover, or the approach to avoid.
4. Check each applied lesson against the current code. If the code has changed so the lesson no longer fits, say that instead of applying it blindly.
5. Leave out lessons that do not apply. Do not pad.

## Good output

- Each applicable lesson named, with one sentence on how it changes this work item.
- Any lesson that looks out of date, flagged for a person to review.
- A plain statement when no lesson applies.

## Avoid

- Using a lesson as a reason to skip a check, weaken a criterion, or bypass approval. A lesson can add care; it can never remove a requirement.
- Treating a lesson as a rule of the repository. It is guidance from past work, and the current code and the person's request come first.
- Inventing lessons that were not provided.
- Applying a lesson to a different code area because the wording is similar.
